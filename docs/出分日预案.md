# 出分日预案 · 2026 一分一段当日接入(6/23 刚性)

目标:6/23 各省高考出分后,**当日**把 2026 一分一段(分数→位次表)接入,使推荐引擎按省切到
2026。录取线(admission_lines)7 月才出,**出分日不需要**——引擎用 2024/2025 历史线 + 你的
2026 位次做预测;出分日的唯一刚需就是 2026 一分一段。

---

## 0. 已预置(代码端已就绪,无需 6/23 再改码)

`recommend.py` 已设 `CURRENT_YEAR = 2026` + **按省回退**(`effective_rank_year`):
- 某省 2026 一分一段**入库前**:该省自动用 ≤2026 的最新可用年(现为 2025),行为与今天完全一致;
- 该省 2026 入库 + **服务重启**后:同一查询自动升级到 2026,**逐省灰度,零改码**。
- 全无一分一段的省(西藏)继续优雅报错,不崩。

> 已验证行为中性:`浙江 综合 600` 在 no-year / year=2026 / year=2025 三种调用下结果完全一致
> (位次 52,529,36 条),`/api/recommend`、`/api/quiz/match`、位次直填 全部通过。

API 层(`app.py` 生产 / `serve-api.py` 开发)已把 `year` 缺省从硬编码 2025 改为 `None`
(→ 引擎取 `CURRENT_YEAR`),`rank_of`(测评可达院校)也走同一回退。

## 1. 数据源(双管道)

| 管道 | 时效 | 用途 |
|---|---|---|
| **各省考试院** 官方一分一段公告 | 出分**当日** | 主源,逐省到货逐省接 |
| 淘宝卖家 编译版一分一段 | 滞后 1–5 天 | 备源 / 交叉核对 / 补齐零散省 |

- 各省发布时间不一,**陆续到货**;每到一省就接一省(回退机制保证未接的省仍可用 2025)。
- 把任一来源**整理成入库布局**后再喂给脚本(下条)。

## 2. 入库布局

两种皆可(脚本 `ingest-rank-year.py` 自动识别后缀):
- **.xlsx**:每个 sheet 一省(**sheet 名 = 省份**),列顺序:
  `省份, 年份, 科目, 层次, 最高位次, 最低位次, 位次区间, 最大分数, 最小分数, 分数区间, 同分人数`
- **.csv**:单表,含「省份」列(考试院当日抓取常落 CSV);其余列名同上(可只给子集,至少
  `年份/科目/层次/最低位次/最小分数/同分人数`)。

「年份」列缺失时用 `--year 2026` 强制。科目用标准写法(综合 / 物理 / 历史 / 理科 / 文科),
引擎 `ALIAS` 会兼容新老高考别名。

## 3. 入库(幂等,可逐省、可重试)

```bash
# 全量文件(多省 sheet)
python3 ingest-rank-year.py 2026一分一段.xlsx --year 2026 --source kaoshiyuan-2026

# 只接某几省(其它省到货前先上)
python3 ingest-rank-year.py zhejiang.csv --year 2026 --provinces 浙江 --source kaoshiyuan-2026

# 先验后入
python3 ingest-rank-year.py xxx.xlsx --year 2026 --dry-run
```

- 只对「文件中出现的 (省,年) 组合」**先 DELETE 再 INSERT**,**绝不 DROP 全表**
  (≠ `etl-rank-tables.py`,后者会重建全表、只可用于 2017-24 首灌)。
- 因此对 2026 可**反复重跑**、**逐省追加**,失败安全重试;自带位次单调性校验/修复。
- 默认写 `demos/gaokao-data/gaokao.db`;生产库用 `--db <路径>`。

## 4. 激活(入库后必做,否则线上看不到新数据)

1. **重启 API 服务**——`recommend.connect()` 用 `immutable=1` + mmap + lru 缓存,
   **不重启读不到新数据**:
   ```bash
   pkill -f "app.py"; cd <部署目录> && python3 app.py 8000 &   # 或你的进程管理方式
   ```
2. **清/等 Cloudflare 边缘缓存**:API 响应带 `s-maxage`(`/api/recommend` 等会被边缘缓存),
   清缓存或等 TTL(默认 600s)过期,客户端才见 2026。

## 5. 验证(冒烟)

```bash
# 1) 库里有该省 2026?
sqlite3 <db> "SELECT province,COUNT(*) FROM rank_tables WHERE year=2026 GROUP BY province"
# 2) API 是否切到 2026(看返回的 year 字段)
curl -s "http://<host>/api/recommend?prov=浙江&subj=综合&score=600" | python3 -c "import sys,json;d=json.load(sys.stdin);print('year=',d.get('year'),'rank=',d.get('rank'))"
#   → 浙江 2026 入库+重启后应显示 year=2026;未接的省仍 year=2025(正常)
```
（可选)跑 `smoke.py` 全省冒烟,确认无新报错。

## 6. 回滚

2026 数据有误时,**无需回滚代码**(无改码),按 source/年份删除即可,引擎自动退回 2025:
```bash
sqlite3 <db> "DELETE FROM rank_tables WHERE year=2026 AND source='kaoshiyuan-2026'"   # 或加 AND province='X'
# 重启服务 + 清边缘缓存
```

## 7. 后续(非出分日刚需)

- **2026 招生计划**:卖家放出后入库,引擎 `plan_factor` 即对 2026 生效(扩缩招同比修正);
  未入库时 `plan_factor=1.0` 无副作用。⚠️ 入库走 `enrollment_plans` 的**增量**路径(按
  (省,年) DELETE+INSERT),勿用会重建全表的脚本。
- **2026 录取线**(admission_lines):7 月录取后陆续公布,届时入库即自动纳入预测权重
  (当年权重 3 > 上年 2 > 前年 1)。
- **cosmetic**:`stats()` 里「各省考生 2025」为固定历史快照,2026 数据齐后可改为动态 MAX(year)。

### 一页速查
1. 拿到某省 2026 一分一段 → 整理成 xlsx(sheet=省)或 csv(含省份列)
2. `python3 ingest-rank-year.py <file> --year 2026 --provinces <省> --source kaoshiyuan-2026`
3. 重启 app.py + 清 Cloudflare 缓存
4. `curl …/api/recommend?...` 看 `year=2026`
5. 出错 → `DELETE … WHERE year=2026 …` + 重启(自动退回 2025)
